# Model Generator Agent

A conversational agent that generates production-ready dbt models following
all jaffle shop project standards. Driven through Claude Code — no scripts,
no external dependencies.

---

## What it does

Given a plain English business description, the agent:

1. **Clarifies** the grain, sources, and downstream consumer if anything is ambiguous
2. **Plans** the model — correct layer, materialization, inputs, columns, and tests
3. **Waits for your approval** before writing a single file
4. **Generates the SQL** following mandatory CTE structure and naming conventions
5. **Generates the YAML** with descriptions and tests for every column
6. **Validates** with `dbt build --select [model]+` and `dbt test --select [model]+`
7. **Reports back** with a summary of what was built and what passed

If a reusable transformation is identified, it will offer to extract it as
an intermediate model or macro before writing the final model.

---

## How to invoke

Open this project in Claude Code, then tell Claude:

> "Act as the model generator agent described in `agents/model_generator/AGENT.md`.
> I want to build a model that [your business description]."

Or more directly:

> "Use the model generator. I need a model that shows monthly revenue by payment method."

Claude will read `AGENT.md` and `CLAUDE.md` and begin Phase 1.

---

## The 5 phases

| Phase | What happens | Pauses for input? |
|-------|-------------|-------------------|
| 1. Understand | Clarifying questions about grain, source, consumer | Yes — if ambiguous |
| 2. Plan | Reads existing models, proposes name/layer/columns | **Yes — always** |
| 3. Generate SQL | Writes SQL following CTE standards | Shows before saving |
| 4. Generate YAML | Adds entry to correct `_[layer]__models.yml` | Shows before saving |
| 5. Validate | Runs `dbt build` and `dbt test` | Reports result |

**The agent will never write a file without showing it to you first.**

---

## Telling the agent which layer to use

If you already know the layer, say so upfront:

> "Generate an intermediate model that..."
> "I need a new mart — specifically a fact table for..."
> "Add a staging model for the new `raw_subscriptions` seed."

If you don't specify, the agent will decide and explain its reasoning in the plan.

## Standards enforced

All models generated by this agent follow:

- Naming conventions from `CLAUDE.md` (`stg_`, `int_`, `fct_`, `dim_`, `_id`, `_at`)
- Mandatory CTE structure: imports → transformations → `final` → `select * from final`
- `{{ ref() }}` and `{{ source() }}` — never raw table names
- YAML with descriptions and tests for every column
- Materialization rules: staging/intermediate as `view`, marts as `table`
- `CLAUDE.md` macro list updated whenever a new macro is created

For the full behavioral spec, read [`AGENT.md`](AGENT.md).
